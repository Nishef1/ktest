# Windscribe upstream compatibility audit — 2026-10-17

> **Historical audit:** findings below describe the public upstream and KTest state inspected on 2026-10-17. Re-check the current code before treating an item as still open or fixed. The current desktop behavior and acceptance boundary are in [WINDSCRIBE_BOOTSTRAP.md](WINDSCRIBE_BOOTSTRAP.md) and [CURRENT_AUDIT_2026-10-21.md](CURRENT_AUDIT_2026-10-21.md). CI success is not proof of an authenticated Windscribe tunnel on a live ISP.

Scope: review **relevant network-path sources**, released changelogs, public PRs/issues across Windscribe Desktop-App, Android-App, wstunnel and wsnet, compared to `Nishef1/ktest`. This is not a claim that every line of the four repositories or private Windscribe issues was inspected. Version context: Desktop stable v2.24.13, 2.25.3-alpha (post-connect validation), newest checked 2.25.4-alpha (Oct 13); wsnet 1.5.39 (Oct 9).

## Verified upstream facts and ktest discrepancies

| Priority | Evidence | Consequence / next action |
| --- | --- | --- |
| **P1** | Official [wstunnel httpClient.go](https://github.com/Windscribe/wstunnel/blob/main/cli/httpClient.go) runs **stunnel** through randomized uTLS (`createRemoteConnection`) but **WStunnel** through a Go WebSocket dialer with the standard TLS stack (`createWsConnection`). [PR #3](https://github.com/Windscribe/wstunnel/pull/3) adds optional custom SNI for both. | ktest currently races `HelloChrome_Auto` and `HelloRandomizedALPN` on **both** outer transports and calls the latter `hello=windscribe`. The WStunnel variant is **not identical** to upstream. Create an official-style Go TLS WStunnel **comparison** candidate, with matched target, Host, SNI and secure validation policy; do not replace successful candidates without an A/B test. Relabel the randomized variant as experimental. |
| **P1** | [Desktop manual attempt strategy](https://github.com/Windscribe/Desktop-App/blob/master/src/client/engine/engine/connectionmanager/attemptstrategy/manualconnectionattemptstrategy.cpp) retries with `selectNextNode()` and stops after two failed manual attempts. [PortMap](https://github.com/Windscribe/Desktop-App/blob/master/src/client/client-common/api_responses/portmap.cpp) selects a protocol-specific IP field. | ktest races up to 24 *outer* carriers **inside one single** OpenVPN CONNECT; that does not force the Windscribe desktop client to try many server nodes. Never count carrier variants as separate verified Windscribe connections; preserve the original inner TCP destination and observe actual node rotation. |
| **P1** | [Android bundled PortMap](https://github.com/Windscribe/Android-App/blob/main/base/src/main/res/raw/port_map.txt) uses `ip2` for OpenVPN TCP, `ip3` for Stealth. The bundled map does **not** specify WStunnel; desktop consumes a dynamic PortMap. | The assumption that WStunnel must use a particular node `ip` or `ip3` cannot be established from the Android fallback file. ktest explores advertised candidates but should record them as unverified until a contemporaneous authenticated PortMap is available. Hardcoded outer port 443 should be benchmarked against the selected protocol's valid ports, not blindly multiplied across destinations. |
| **P1** | [wsnet CHANGELOG 1.5.33](https://github.com/Windscribe/wsnet/blob/master/CHANGELOG.md) exposes `fd:1` draining nodes; [inventoryparser.cpp](https://github.com/Windscribe/wsnet/blob/master/src/apiresourcesmanager/inventoryparser.cpp) reads integer `fd == 1`. | **Fixed in ktest**: skip draining nodes on catalog parse. Regression test added. |
| **P1** | [CLI strings.cpp](https://github.com/Windscribe/Desktop-App/blob/master/src/windscribe-cli/strings.cpp) emits `Connected` without a city when location is invalid and may prefix the line with `*` (test pending) or append `[Network interference]`. | **Fixed in ktest**: parse both `Connected` and `Connected: City`, while still treating pending or interference labels as unverified. |
| **P1** | [wsnet 1.5.37](https://github.com/Windscribe/wsnet/blob/master/CHANGELOG.md) adds `WSNetTunnelTest`, IP checks and cancellation of stale post-disconnect results; [Desktop 2.25.3](https://github.com/Windscribe/Desktop-App/releases/tag/v2.25.3) enhances post-connect IP/tunnel validation. | A structurally valid initial OpenVPN reply is *not* a working VPN. Attribution also requires an actual Windscribe TCP Connected transition and ideally route/exit-IP validation. When the VPN exits or a new session replaces it, invalidate results tied to the previous session. Do not mislabel blocked check-IP endpoints as cryptographic handshake failure. |
| **P1** | ktest `cmd/ktest/windscribe_wstunnel.go` currently waits only 8 seconds on catalog `ready`; `cmd/ktest/connect.go` uses HTTP client Timeout 10 seconds, and the catalog updater tries v2 and fallback URLs sequentially for each source. | **Cold-start timing mismatch**: an uncached server catalog can be unavailable when the first CONNECT race begins, removing all WStunnel/Stealth candidates. Need a bounded ready-on-first-valid-source notification and a test with slow primary but fast fallback; no fabricated entries. |
| **P2** | [wsnet 1.5.35](https://github.com/Windscribe/wsnet/blob/master/CHANGELOG.md) keys Bridge API tokens by **node ID**, not hostname: multiple nodes may share a hostname, and late replies must not update a newer connection. | ktest does not use this token mechanism, so it must not treat wsnet API success as data-plane tunnel proof. If adding provider Bridge API verification, bind tokens and asynchronous checks to the precise node/session ID, not just the requested country or hostname. |
| **P2** | [Desktop 2.24.2/2.24.3](https://github.com/Windscribe/Desktop-App/blob/master/CHANGELOG.md) introduced and limited Custom SNI to WStunnel/Stealth; [official PR #3](https://github.com/Windscribe/wstunnel/pull/3) makes overriding SNI optional. | ktest defaults to three unrelated SNI hostnames on direct transport. These are experiments, not necessarily a reference profile. Test provider-native no-custom-SNI first in isolation, followed by carefully controlled alternatives. A hostname-looking string alone is not authenticated CDN fronting. |
| **P2** | [wstunnel official TLS](https://github.com/Windscribe/wstunnel/blob/main/cli/httpClient.go) defaults to `InsecureSkipVerify` for outer TLS. ktest checks certificate name suffix, but does not establish a complete chain when custom SNI overrides the actual node name. | This is a **security boundary gap**, not an excuse to remove Windscribe's authenticated inner OpenVPN checks. Use a distinct trust policy for exact provider-hostname TLS and a documented experimental SNI mode; never report full outer certificate verification based on suffix matching. |
| **P2** | [wsnet 1.5.17](https://github.com/Windscribe/wsnet/blob/master/CHANGELOG.md) removed its own TLS custom curves to avoid an identifiable fingerprint. ktest constrains randomized uTLS curves because its pinned library failed on unsupported key exchange groups. | Practical compatibility workaround can make the ClientHello fingerprint different from official Stealth. Call it a randomized **alternative**, not a byte-for-byte Windscribe profile, and compare real handshakes with the official binary. |
| **P2** | [Desktop #338](https://github.com/Windscribe/Desktop-App/issues/338#issuecomment-5094367590): Windscribe stated it **added** `J - Iran Junk Packets` on the **server side** and that this profile applies to WireGuard and OpenVPN **UDP**. | Do **not** infer that selecting J improves OpenVPN **TCP** with ktest HTTP CONNECT; server-side compatibility and protocol type matter. Separate UDP+J experiments from TCP+WStunnel/Stealth experiments. |
| **P2** | [Desktop #371](https://github.com/Windscribe/Desktop-App/issues/371) reports one Location succeeds while another with same protocol fails. [Desktop #365](https://github.com/Windscribe/Desktop-App/issues/365) reports per-location regressions within an unrelated proxy chain. | Location/IP-specific failures occur outside ktest too. These user reports support testing route/server differences, **not** a conclusion that DPI or provider infrastructure is definitely the culprit. |
| **P2** | [Android #67](https://github.com/Windscribe/Android-App/issues/67) described a working custom tunnel torn down by a blocked `checkip` health endpoint; maintainer reports the custom-config health check was removed in Android v4.2. [Android #73](https://github.com/Windscribe/Android-App/issues/73) flags pre-connect connectivity detection. | Separate pre-connect reachability, successful cryptographic handshake and post-connect test endpoints. A blocked health-check service can produce a false negative. This is most directly supported for Android/custom WG profiles; do not claim it explains unverified Windows OpenVPN TCP resets before certificate validation. |
| **P2** | [wsnet 1.5.31/1.5.32](https://github.com/Windscribe/wsnet/blob/master/CHANGELOG.md) applies scoped exponential API backoff and distinguishes retryable 5xx/timeouts from 403/429/captcha. | HTTP/API failover rules cannot be reused blindly for VPN data-plane handshake failure. Every retry decision must be classified by layer and bounded by operator/user budget. |
| **P2** | [Android #65](https://github.com/Windscribe/Android-App/issues/65) requests CDN ingress for the VPN **data plane**, explicitly distinct from wsnet CDN/API failover. | Treat customer-configured CDN edge->origin routing as a separately provisioned infrastructure prerequisite, not a magic ClientHello/SNI toggle. A reachable API/control plane does not imply an accessible Windscribe tunnel. |

## Public repository limitations and evidence strength

- Desktop v2.24.13 is the latest stable release found on October 17, 2026; v2.25.4 (October 13) is alpha and notes a Linux regression from v2.25.3, plus packaging/tapctl updates. Alpha changes may not be present in the user's installation.
- Public Desktop-App PR listings largely expose community submissions; changelog references such as `#1969` and some internal fixes cannot be reconstructed as merged public PR diffs from this mirror. Do not invent unseen review conclusions.
- Issue observations are **user reports**, not controlled experiments. Protocol, client version, ISP, target node IP, health state and TLS certificate verification can all differ.
- The ktest race currently picks the first OpenVPN-shaped control packet before Windscribe authentication. Once a stateful TLS/OpenVPN negotiation starts, changing the upstream node mid-stream is unsafe. Failover must be a separate complete CONNECT or controlled application-level reconnect.

## Ordered next experiments / engineering work

1. Fix catalog cold-start notification/budget; demonstrate a fresh cache and a slow primary API still yield healthy node candidates.
2. Compare the **official Go TLS WStunnel dialer** against ktest's existing Chrome and randomized uTLS candidates on identical IP/port/Host/SNI and network. Preserve valid WebSocket framing and verified inner OpenVPN state.
3. Add an optional provider-native no-custom-SNI baseline, and obtain the *current* dynamic WStunnel port mapping before excluding or reclassifying IPs.
4. Use per-attempt stage logs: requested OpenVPN ip2, physical outer entry, carrier type, TLS fingerprint, SNI, HTTP Host/path, network error, first valid control packet, CLI Connected/pending/interference, exit-IP check. Group by exact ISP/time/node rather than just country.
5. Benchmark controlled A/B within the same network: direct TCP/443, ktest raw local path, Stealth `ip3`/valid port, WStunnel via official wrapper, ktest WStunnel variants. **No UDP/J result** can validate the TCP bridge.
6. Defer any claim of DPI bypass or percentage gain until repeatable connection-success and independent HTTPS egress are measured.
