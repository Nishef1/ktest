# Aether v2.4.0 upgrade audit — 2026-10-24

Scope: PattN 7.25.6-P37, PattNG 2.3.13-P68 and patterniha/Aether v2.4.0 compared with KTest. This is code-level integration, not a live Iranian ISP measurement.

## Implemented integration

- Native upgrade: use the existing feature-branch updater to verify GitHub release digests, Android ELF headers and individual executable SHA-256s. Pin all desktop and Android artifacts to the same release. Never overwrite an active binary or saved identity.
- Registration: direct HTTPS with upstream core API name/Cloudflare edge fallbacks now remains available even if optional local anti-DPI carrier setup fails; retain separate fragmented, ECH, Psiphon and explicit local proxy attempts.
- H2: preserve `--masque --h2`, IPv6 and non-ECH profiles; updated upstream core handles revised TLS fingerprints, gateway scan/ports, and reconnect strikes/cooldowns.
- Endpointless profiles: omit forced `--peer`; `--quick-reconnect` checks cached working peers and falls back to a native scan. KTest still verifies outbound data and manages policy across backends.
- Tests: offline direct/fragmented route ordering, implicit endpoint/quick reconnect, platform-version parity and existing key staging/cancellation.

## Acceptance gates (not claimed complete)

1. Real Android: WARP key registration without another VPN on networks that allow a Cloudflare API edge; blocked API failures preserve existing keys. Confirm new signed APK actually contains the updated native core.
2. H2 IPv4/IPv6, H3 and WireGuard: fresh and cached connection, refused cached gateway, repeated short drops, healthy long tunnel after handover, explicit disconnect.
3. 20 connect/disconnect cycles, Wi-Fi↔cellular, DNS/IPv6 leak checks, successful HTTPS through the full TUN path; distinguish SOCKS listener from verified carrier and actual foreign egress.
4. P50/P95 startup and CPU/RAM/battery measurements; compare on same device and network before calling the upgrade faster or more reliable.

Rollback: Windows retains prior core generations and private key files; Android requires a compatible signed APK and preserved app-private storage, not an in-place native executable replacement.
